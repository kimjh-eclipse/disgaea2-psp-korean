# 규명한 포맷

## NIS LZS (`tools/nislzs.py`)

```
+0x00  "dat\0"
+0x04  u32 decompressed size
+0x08  u32 compressed size
+0x0C  u8  flag
+0x10  data
```

토큰은 `[flag][x][cnt]`, `disp = (x > flag) ? x-1 : x`.

> **게임 디코더는 겹치는 복사를 지원하지 않습니다.** 인코더가 `cnt > disp` 인 토큰을 내면
> 그 뒤 전부가 깨집니다. 파일 자체 왕복 검사로는 잡히지 않아 RAM과 대조해야 발견됩니다.
> 그래서 압축 후 비중첩 제약을 별도로 검사합니다.

## NISPACK (`tools/scriptpack.py`)

```
+0x00  "NISPACK\0"
+0x0C  u32 count
+0x10  entry[count]  각 0x20 바이트 { u32 offset(+0x2B0 보정), char name[0x1C] }
```

멤버는 0x800 정렬. **마지막 멤버 뒤에는 패딩을 넣지 않습니다** — 넣으면 크기가 달라집니다.

`SCRIPTPACK`(34) `TXPPACK`(220) `MAPPACK`(287) `ANMPACK`(337) 등이 이 포맷입니다.

## TXP 텍스처 (`tools/txp.py`)

```
+0x00  u16 w, u16 h
+0x0A  u16 pb        팔레트 블록 수 (색 수 = 16*pb)
+0x10  팔레트 RGBA (색 수 × 4)
       픽셀 (4bpp: w*h/2, 8bpp: w*h)
```

**스위즐 여부가 파일마다 다릅니다.** 폰트 페이지는 16×8 블록 스위즐, `name.txp`는 리니어입니다.
잘못 고르면 노이즈가 됩니다.

알파는 0~128 범위라 표시할 때 2배 해야 합니다.

## talk 바이트코드 (`tools/talkfile.py`)

```
+0x00  u32 count
+0x04  u32 count (중복)
+0x08  record[count]  각 0x20 바이트, +0x00 = 스트림 오프셋
       이후 바이트코드 스트림. 문자열은 01 <SJIS...> 00 인라인
```

길이를 바꾸면 모든 레코드의 스트림 오프셋을 보정해야 합니다(`rebuild`가 처리).

> 선행바이트 범위는 `0x81-0x9F` / `0xE0-0xFC` 입니다. 한글 코드가 `0xF0~0xFC` 이므로
> `0xEF`까지만 보면 번역된 파일의 문자열을 탐지하지 못합니다.

`01 <str> 00` 프레이밍에 우연히 맞는 **바이트코드 오검출**이 6건 있습니다(`d孛` 등).
주변이 `ff ff 00 00 00 0e` 같은 테이블이며, 건드리면 스크립트가 깨집니다.

## 고정 레코드 DB 6종 (`tools/recdat.py`)

```
+0x00  u32 count ×2
+hdr   record[count]  각 rs 바이트, 문자열 필드는 고정 오프셋·고정 폭
```

| 파일 | hdr | rec | 텍스트 필드 | 고유 | 내용 |
|---|---:|---:|---|---:|---|
| HABIT.dat | 8 | 120 | 0x00/21, 0x15/87 | 1,141 | 무기·기술명 + 설명 |
| dungeon.dat | 8 | 64 | 0x00/64 | 122 | 이노센트·던전 |
| charhelp.dat | 8 | 80 | 0x00/22 | 132 | 맵 이름 |
| magic.dat | 8 | 152 | 0x00/50, 0x32/50, 0x64/50 | 364 | 마법 설명 3줄 |
| mitem.dat | 16 | 104 | 0x08/24, 0x20/72 | 172 | 음악방 |
| music.dat | 8 | 140 | 0x28/47, 0x57/53 | 113 | 의회 의제 |

talk과 달리 **필드 폭이 고정**입니다. 종단 NUL 1바이트를 빼면 가용은 `폭-1`이고,
한글은 2바이트/음절이라 예산 20이면 10자입니다.

필드 자동 탐지는 4바이트 정수 필드를 문자열로 잡으므로, 실제 텍스트 필드만 등록해야 합니다.

## 대사창 이름표 — 루트 `CHAR.DAT`

`sys2.txp`(START 안, 500레코드)와 루트 `CHAR.DAT`(396레코드) 양쪽에 이름이 있는데,
**화면에 쓰이는 것은 루트 `CHAR.DAT`** 입니다. 두 ISO의 레코드 288(`ママ`)만 다르게 만들어
확정했습니다.

`TXPPACK/name.txp`(256×256 리니어 4bpp)도 이름 이미지 아틀라스이지만 대사창 출처는 아닙니다.
사용처는 미확인입니다.

## 유닛 기본 이름 풀

루트 `NAME.DAT`(오프셋 테이블 + SJIS 블롭, 910개)는 **게임이 쓰지 않습니다.**
실제 사용처는 `START_VM_JP.LZS` 를 해제한 이미지 안의 NUL 종단 가변길이 블롭입니다.
오프셋 테이블이 딸려 있어 각 이름의 바이트 길이를 유지해야 합니다.
